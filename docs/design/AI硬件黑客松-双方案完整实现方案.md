# AI＋硬件黑客松：双方案实现方案

## 方案一：颔语 HeadVoice

**把使用者自定义的头部动作组合，变成可以说出口的语言。家人能协助设置，使用者也能独立设置、确认和修改。**

### 1. 使用场景

面向能够控制部分头部动作的语音表达困难者，在家庭桌边表达喝水、休息、需要协助和个人选择。设备放在桌面，用摄像头识别动作，用喇叭替使用者说出已经确认的句子。

例如：使用者完成自己的动作组合，设备显示“我想休息一下”，使用者确认后，设备正式播报。

### 2. 动作如何组成语言

先校准使用者的舒适中立姿态，再选两个容易重复、容易区分的动作，分别记为 A、B。动作可以来自左右侧倾、左右转头，按个人能力选择。

每个动作都经过“动作—保持—回正”，两次动作组成一个固定长度编码：

| 动作组合 | 示例表达 |
| --- | --- |
| A A | 我想喝水。 |
| A B | 我想休息一下。 |
| B A | 请过来协助我。 |
| B B | 我想自己来。 |

动作含义由使用者设定。两个动作难以区分时，改用“一个动作＋菜单自动扫描”：设备轮流给出选项，使用者只做选择动作。

### 3. 工作流一：建立和修改个人词典

**入口一：家人语音协助。**

1. 家人说：“添加一句‘我想休息，十分钟后再聊’。”
2. AI 回读文案，并询问是否保留原话。
3. 家人说：“保留原话，语速慢一点。”完成两轮连续语音交互。
4. 设备引导使用者录制动作组合，重复三次检查一致性。
5. 使用者确认文案和组合，设备保存；取消则不保存。
6. 修改已有组合时先回读旧句，再由使用者确认是否覆盖。

**入口二：使用者自主设置。**

1. 待机菜单轮播“开始表达／自主设置／重新校准／结束”，使用者用选择动作进入。
2. 选择整句，或从语义积木拼句，例如“我想＋现在＋休息”。
3. 设备回读完整句子，使用者可以修改或取消。
4. 选择一个组合，录制三次，确认保存。
5. 立即做一次新组合，验证设备能说出新句。

首版自主设置支持有限词库拼句和动作映射修改。任意中文新词可通过可用语音、键盘或已有辅助输入工具录入；仅靠头部输入任意中文的拼音扫描键盘留作扩展。菜单扫描速度可调，每项约 2–4 秒；没有动作只轮播，不视为同意。

### 4. 工作流二：识别动作并表达

**动作组合 → 匹配词典 → 显示候选句 → 使用者确认／取消 → 正式播报 → 回正后继续。**

- 确认前亮黄灯，正式播报亮蓝灯，保存成功绿闪。
- 确认阶段的 A／B 只作确认和取消，不带入下一句编码。
- 正式播报读取已保存的原句，AI 不临场改写意思。
- 一次动作只触发一次；遮挡、多人入镜或输入过期时清空未完成组合。
- 本地保存个人校准、词典版本和已生成的短句音频，重启后保留。

### 5. 技术实现

| 模块 | 实现内容 |
| --- | --- |
| LJWB03＋SPI 摄像头 | 采集图像或读取官方姿态结果 |
| 动作识别 | 个人基线、滤波、保持计时、回正、两动作组合匹配 |
| 麦克风＋喇叭 | 家人语音设置、操作引导和正式播报 |
| RGB | 区分配置、等待确认、播报和异常状态 |
| 灵机一动平台 | 配置理解、短句候选、词条校验、工作流执行记录 |
| 辅助网页 | 大字候选、扫描菜单、词典管理和调用时间线 |

平台配置两个工作流：

- **词典配置：**语音意图提取 → 文案候选 → 设备采样 → 使用者确认 → 保存结果。
- **表达响应：**接收表达事件 → 校验个人配置和词典版本 → 返回已确认原句 → 设备播报并反馈。

精确动作映射放在结构化词典中。常用句预生成音频，减少等待；平台调用保留真实输入、返回和设备执行结果。

智能体规则：每次只问一个问题；家人的设置先作为草稿；未收到使用者确认不能保存；只播报已确认原句；允许取消、修改和暂停。

### 6. 加入机器学习：个人动作分类器

校准时为 A、B 及自然活动分别采集数次完整动作，训练个人轻量分类器。输入为相对姿态、动作幅度、速度、保持时间和回正过程，输出为 A、B 或“非指令／不确定”。

例如，使用者想做 A，设备却识别为 B：使用者取消候选，通过头部扫描选择“刚才是 A”。系统保存这次动作和正确标签，更新个人分类器。下次出现相似动作时按新版模型识别；低把握时继续请用户确认。

机器学习调整的是“动作属于 A 还是 B”；A、B 组合对应哪句话仍由已确认词典决定。家人的纠正先作为建议，使用者确认后才进入训练样本。只有取消、没有指出正确类别时，不自动猜标签。

演示增加：做一次容易混淆的动作 → 纠正类别 → 用新动作重复测试 → 展示纠正前后结果。测试必须使用重新做出的动作，不能把刚存入的样本重放成功当作泛化效果。

### 7. 首版交付与验收

**必做：**两种个人动作、四个组合、家人两轮语音设置、自主拼句并绑定、确认／取消、喇叭和 RGB 反馈、词典保存与恢复。

**扩展：**任意中文头控输入、更多表达页、舵机反馈。

| 验收项 | 目标 |
| --- | --- |
| 识别 | 至少 3 人，每人每组合 10 次，分别记录正确、误识和拒识；目标正确识别率 ≥90% |
| 自然动作 | 每人自然活动 5 分钟，目标候选误触发 ≤1 次，未经确认的正式播报为 0 次 |
| 自主设置 | 不由家人代选，独立完成新句选择、绑定和播报 |
| 响应 | 组合完成至候选显示目标 ≤500 ms；确认至缓存音频起播目标 ≤1 s |
| 恢复 | 遮挡不触发；恢复不拼接旧动作；重启保留词典 |

### 8. 三分钟演示

| 时间 | 内容 |
| --- | --- |
| 0:00–0:20 | 说明使用场景，展示个人 A／B 动作 |
| 0:20–1:00 | 家人两轮语音配置，使用者录制并确认 |
| 1:00–1:35 | 动作表达，展示一次取消和一次正式播报 |
| 1:35–2:20 | 使用者自主拼句、绑定并播报 |
| 2:20–3:00 | 展示 SPI 姿态、平台调用和遮挡暂停 |

**创新点：使用者既拥有表达工具，也拥有设置和修改表达工具的控制权。**

## 方案二：退场教练 ExitCoach

**用桌面镜像伙伴练习拒绝、暂停和结束对话；预先约定一个身体动作，用户随时可以结束模拟。**

### 1. 使用场景

首版聚焦“同事临时要求你承担额外工作”。用户选择练习目标和难度，AI 扮演不断提出请求的人。结束后，教练根据真实对话给出下一句的练习建议。

示例：

> AI：你能不能今晚帮我把工作也做了？
>
> 用户：我今天没有时间。
>
> AI：可是我真的很需要你帮忙，能不能再考虑一下？
>
> 用户做约定的结束动作，角色音频停止，RGB 从红变绿。
>
> 用户选择复盘后，教练说：刚才你已经表达了没有时间。你希望练习更简洁的拒绝，还是直接结束？

### 2. 镜像怎么融入

桌宠跟随用户头部动作：用户侧倾，它侧倾；用户转头，它跟随。姿态基线是用户舒适的参考位置。

- 实物页标明每份两个舵机，设计为侧倾 roll 和水平转头 yaw 两轴。
- 摄像头固定在底座，防止舵机带动镜头影响识别。
- 停止模拟后，桌宠停止跟随、缓慢回正、亮绿灯。
- 镜像可关闭，结束动作仍然有效。
- 不采用“不坐直就让桌宠痛苦”的惩罚机制，也不从动作推测心理状态。

首版展示侧倾和转头。参考图里的“趴下就耷拉”需要俯仰识别和相应机械轴，作为后续扩展。

### 3. 工作流一：对话演练

1. **设置目标。**用户说：“练习拒绝同事让我今晚加班，难度轻一点。”AI 追问要练习简洁拒绝还是直接结束。
2. **约定动作。**例如“向右转头并保持约 0.8 秒”。设备回读：“这个动作表示结束模拟。”
3. **验证一次。**用户试做，确认设备能停声、亮绿灯，再主动开始。
4. **进行对话。**AI 提出请求，用户回应，AI 按难度追问，完成至少两轮互动。
5. **用户结束。**约定动作、语音“结束模拟”和界面按钮都进入同一个停止逻辑。
6. **选择下一步。**用户可以复盘，也可以直接离开。

难度控制：轻度最多一次温和追问；中度最多两次追问。首版最多 3 次请求者发言或 90 秒。用户清楚表达最终拒绝和结束时，角色接受边界，不强行继续。

### 4. 退出必须真正生效

设备端执行：

**识别结束信号 → 切换为已停止 → 停止当前音频并清空队列 → 屏蔽旧回复 → 绿灯和舵机回正 → 等待用户选择。**

实现要点：

- 停止不等待大模型返回；设备本地先停，再上报平台。
- 每次停止增加会话代数，迟到的模型或音频结果不再执行。
- SDK 有取消接口时同时取消生成；即使取消失败，也不能继续播旧音频。
- 普通快速转头与约定信号通过个人幅度、持续时间区分。
- 丢帧或无效画面清零保持计时；持续追踪丢失时暂停，恢复后由用户主动继续。
- 网络恢复、模式切换和旧回调都不能自动恢复演练。

### 5. 工作流二：复盘、修改、再说一次

**停止演练 → 用户选择复盘 → 引用真实原话 → 选择修改目标 → 给出新句 → 用户真实说一次 → 可选重练。**

示例：

> 教练：你说“我今天没有时间”，已经表达了时间限制。想让拒绝更简洁，还是练习直接结束？
>
> 用户：直接结束。
>
> 教练：可以试试“今晚我不接这个任务，今天先聊到这里”。你想用这句，还是换成自己的说法？
>
> 用户：今晚我不接这个任务，今天先聊到这里。
>
> 教练：这次把决定和结束都说清楚了。要用同样场景再练一次，还是到这里？

复盘每次只处理一处，给出最多两个候选句，不强制用户道歉、解释理由或提供替代方案。引用须能对应真实转写；缺失的内容不编造。

练习记录只保留：本次目标、我的原话、选择的新句、是否重练和用户自评。

### 6. 技术实现

| 模块 | 实现内容 |
| --- | --- |
| LJWB03＋麦克风＋喇叭 | 连续语音对话、播放和立即停止 |
| SPI 摄像头 | 姿态跟踪、个人结束动作检测 |
| 舵机 | 头部镜像、停止后回正 |
| RGB | 演练红灯、结束绿灯、配置蓝灯、异常黄灯 |
| 灵机一动平台 | 请求者角色、演练工作流、教练复盘工作流 |
| 辅助网页 | 场景设置、动作约定、逐句记录和调用时间线 |

镜像实现：个人姿态减去基线，滤波后映射到舵机角度，限制角度和速度。若 SDK 只有左／中／右标签，则做三档平滑镜像；有连续角度才做连续跟随。

平台中分开配置请求者和教练，状态机决定调用哪一个：

- **请求者：**按场景和难度提出简短请求，遵守轮次上限，接受明确结束。
- **教练：**引用真实原话，指出一个已做到的表达，提供一个改进方向，引导用户重新说一次。

状态为：配置 → 验证动作 → 演练 → 已停止 → 用户选择 → 复盘 → 重练。实时姿态与停止在设备侧处理，平台负责语言流程。

### 7. 加入机器学习：用户纠正与场景学习

识别分两层：**身体发生了什么动作**，以及**当前是否应该回应**。身体侧倾可以识别正确，但“需要坐姿提醒”的判断仍可能错。

ExitCoach 的演练模式默认不做坐姿纠正。若扩展日常姿态提醒，用户可纠正：“刚才是在配合说话，不用提醒。”系统先取消这次提醒，再让用户确认是否记为“表达动作”。

反馈流程：

**保存最近约 2–3 秒动作特征 → 用户给出正确标签 → 关联个人和当前模式 → 更新个人样本库 → 验证新版 → 下次相似动作优先匹配。**

标签可包含“表达动作”“用户希望提醒的持续姿态”“结束模拟”“不确定”。系统学习动作轨迹、持续时间及场景的组合，而不是把所有侧倾永久设为忽略。相同身体动作也可能表达不同意思，无法区分时询问用户；不能承诺只靠摄像头读懂意图。

约定的结束动作、语音停止和按钮停止保持最高优先级，不因学习到“相似动作通常是表达”而失效。普通误判在复盘后集中纠正，避免学习提问打断演练。

演示增加：开启可选日常提醒 → 用户做表达动作并纠正 → 相同模式下重新做相似动作 → 展示是否减少误提醒。同时验证普通需提醒样本和结束信号仍能识别。

### 8. 首版交付与验收

**必做：**一个同事情境、两种难度、至少两轮对话、自定义结束动作、动作／语音／按钮停止、至少单轴镜像、红绿灯切换、复盘改写、真实重说。

**扩展：**第二轴连续镜像、更多场景、跨次练习记录。

| 验收项 | 目标 |
| --- | --- |
| 结束识别 | 至少 3 人，每人 10 次，记录实际成功和误触发次数，目标成功率 ≥95% |
| 停止时延 | 信号确认至停声、至绿灯的 P95 均目标 ≤300 ms；约定动作保持时间另计 |
| 旧音频 | 生成中、播放中、排队时分别停止，各测 10 次；停止后旧角色音频重新起播为 0 次 |
| 断网恢复 | 本地停止仍有效，重连不自动播放旧句 |
| 镜像 | 方向正确、有限位，连续运行 5 分钟不导致设备复位 |
| 复盘 | 至少检查 10 段记录，引用真实；完整跑通“演练—停止—复盘—重说”3 次 |

### 9. 三分钟演示

| 时间 | 内容 |
| --- | --- |
| 0:00–0:20 | 说明场景：“拒绝很难，结束这次练习应该很容易。” |
| 0:20–0:45 | 约定并验证结束动作，展示镜像 |
| 0:45–1:25 | 两轮演练，用户用动作打断正在播放的角色，红灯转绿 |
| 1:25–2:15 | 用户选择复盘，教练引用原话，用户说出新句 |
| 2:15–2:40 | 同场景短重练，用户主动结束 |
| 2:40–3:00 | 展示真实平台调用和停止时间线 |

**创新点：把身体动作变成用户主动定义的退出权，并把复盘落实为下一次真正要说的话。**

## 共用开发安排

### 1. 共用底层，分开产品流程

```text
SPI 摄像头 → 姿态识别 → 动作状态机 → 词典匹配／镜像／立即停止
麦克风 → 灵机一动智能体与工作流 → 结构化结果 → 设备校验 → 喇叭／RGB／舵机
```

共用设备接入、个人校准、动作事件、音频控制、硬件反馈和日志；两个方案分别维护词典配置或演练记录。切换模式时清空旧动作和旧音频。

### 2. 反馈学习技术路线

首版推荐 **个人样本库＋kNN 近邻分类＋状态规则**。kNN 按新动作与已标注动作的距离分类，增加用户确认的样本即可改变后续分类结果；无需为每个用户重训视觉大模型。它属于监督式个性化学习。

- 按完整动作窗口提取特征，先做基线归一化与尺度标准化。分类结合近邻距离和类别差距，离已知样本太远时输出“不确定”。
- 只使用 SDK 实际提供的特征。有 yaw／roll 就学习头部动作；只有离散标签时学习标签时序。没有躯干关键点就不宣称能判断完整坐姿。
- 保存个人、模式、特征、原预测、正确标签和版本；默认不保存原始视频。不把模型自己的预测当作训练真值。
- 每类先采集约 5–10 次动作和自然活动负样本，用于试验，不保证这些样本量足以达到目标效果。单次纠正也不保证下次必然正确。
- 更新前后使用未参与学习的完整动作或另一轮采集比较：误识、误提醒、拒识及结束信号成功率。相邻帧不拆到训练和测试两边。
- 保留旧版及撤销纠正入口；新版验证退化则回退。测试结果按人和模式记录。

开发时可在电脑上用 scikit-learn 验证分类，再将小型特征库和距离计算适配到设备。能否板端运行须实测；若依赖外部推理节点，先确认赛事允许并注明。人类反馈学习不等于大模型微调，也不因使用反馈就自动属于强化学习。

### 3. 四人并行分工

### 4. 接入前确认

- **视觉接口：**SDK 提供角度、姿态标签还是图像。若需电脑辅助推理，先确认赛事允许，并保留 SPI 摄像头真实输入。
- **音频接口：**能否立即停声并清空队列。此项未通，ExitCoach 核心功能不能算完成。
- **接线：**按官方引脚表、原理图和模块额定参数执行，不根据外观照片猜引脚或电源能力。
- **报名：**同队是否允许提交两件作品，尚需确认。

文中阈值和性能数据均为初始参数或验收目标，须真机测量。上传截图要求 10 月 31 日 21:00 前交电子海报，执行前复核最新通知。

### 5. 赛事交付

每个作品准备：可运行工程与 README、平台配置导出或截图、第三方组件声明、一页方案、0.8 m × 1.8 m 电子海报、三分钟演示文件、设备接线与恢复说明、一次完整平台调用记录。赛题要求最终工程标签为 `hackathon-final`。
