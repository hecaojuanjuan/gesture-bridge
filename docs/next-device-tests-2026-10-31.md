cd /Users/emt/Workspace/hackathon/gesture-bridge

下面的命令沿用同一个终端里的 `PY` 和 `PORT`。原始串口日志及真人画面只保存在 Git 忽略的 `.local/`；串口原始日志可能夹带云端消息，反馈时请发摘要或错误文字，不要整份复制。

HP 有效性与目标缓存修复已随当前自检固件上板；旧有效帧失效及恢复的实机边界仍待验收，手机快照始终不能代替 USB 连续时序验证。第 4 步手机灯控可独立测试。

用户已退出手动串口会话，后续自检和采样均未发送舵机运动命令。Chrome 与终端不可同时读取 USB；使用网页校准取景后，先断开网页 USB，再启动日志采集。

## 1. 本地面板与取景

1. 在 Chrome 打开 `http://127.0.0.1:4173/`。若网页没有运行，另开一个终端执行下面的启动命令；保持该终端运行，并以它实际显示的本地地址为准。
2. 点击 **连接 USB 设备**，选择 CH343。等待“设备已响应”，核对“姿态诊断”区域的阶段标签显示 **姿态诊断**（对应固件 stage 2；另外两种阶段为“采集”和“动作表达”）。
3. 点击 **获取画面**，等待一张完整画面。记录是否显示 `160 × 120`、获取耗时、正脸是否完整居中、是否有强背光或明显偏色。页面显示的是低帧率单帧预览；约 7–9 秒包含串口分块传输与页面接收，不能当作姿态模型推理耗时。
4. 等画面传输完成，再看“姿态诊断”的**检测目标数**是否偶尔为 1、倾角是否出现、随后是否掉回 0。页面的 `people=1` 在 face 后端表示一张可见人脸，不代表全身人数。取帧时姿态显示会暂停，结束后恢复。

```sh
# 仅当 4173 页面未运行时，在另一个终端启动；已经打开则跳过。
npm --prefix panel run dev -- --port 4173 --strictPort
```

本步骤请反馈：页面是否连上、stage、画面尺寸和用时、脸在画面中的位置、目标数在约 20 秒内是稳定为 1 还是 0/1 跳变。当前发布 H5 v2 已包含电脑 USB 画面和被动姿态诊断，但手机灵机只提供云端状态快照，不能使用电脑的 Web Serial 图像通道；手机没有画面不能作为摄像头故障证据。

## 2. 改变一个条件后，采集新的正脸样本

第二轮“已对准正脸”的 60 秒结果已经保存，**不要原样重复**。先根据第 1 步画面只改变一个明显条件，例如让光照来自脸的前方、避开背后强光，或调整距离让整张脸与下巴都在画面中；把改动记下来。测试时保持正脸和坐姿稳定。

在 Chrome 点击 **断开**，确认自动刷新已停止，再执行一次 60 秒被动采样。这个脚本只监听日志，不发送灯光、舵机或配网指令。采样期间不要用 Chrome 取画面、运行别的串口程序或触碰 USB 线。

```sh
"$PY" tools/capture_serial.py --port "$PORT" --seconds 60 --quiet \
  --output .local/manual-tests-20261031/frontlit-neutral.jsonl
"$PY" tools/pose_readiness.py \
  .local/manual-tests-20261031/frontlit-neutral.jsonl \
  > .local/manual-tests-20261031/frontlit-neutral-report.json
"$PY" -c 'import json,sys; r=json.load(open(sys.argv[1])); print("samples:",r["samples"],"tracked:",r["tracked_samples"],"longest_ms:",r["longest_segment_span_ms"],"whole_log_passed:",r["timing_gate_passed"],"any_segment_passed:",any(s["timing_gate_passed"] for s in r["segments"])); print("reasons:", *r["reasons"], sep="\n- ")' \
  .local/manual-tests-20261031/frontlit-neutral-report.json
```

记录末尾若出现 `partial_line`，分析脚本会忽略未收到换行的尾片段。**验收口径**：至少一个连续片段包含不少于 30 条追踪观察、覆盖不少于 30 秒；结果帧龄、相邻采集间隔，以及“前一帧采集到下一帧结果”的时间都要不超过 400 ms。`any_segment_passed` 只是时序门槛，仍不能证明中立姿态稳定或动作准确。若失败，把命令的短输出和你改变的条件发给我，先暂停后续动作验收。

## 3. 左右侧倾、遮挡与回正（第 2 步出现持续单脸后）

重新用 Chrome 连接 USB。画面导出结束、姿态读数恢复后，按下面顺序各保持约 5 秒，动作以自己舒适的幅度为准：正视 → 向自己左侧倾 → 回正 → 向自己右侧倾 → 回正；随后用手短暂遮住双眼附近，再放开。记录每段面板中的目标数、倾角正负与大致数值、是否标为有效或过期，以及遮挡后能否重新出现单脸。

这一步只检查 **face stage 2 的二维眼线读数**。左右是否符合 A/B 定义需要比较两侧符号；当前固件没有 stage 3 动作编码、确认与播报，不应期待灯圈因侧倾自动亮起或喇叭播报。若任一方向持续掉成目标数 0，请记录发生在哪个方向，不必强行继续保持姿势。

## 4. 手机云端灯控（与姿态测试分开做）

在手机灵机重新进入“奶龙” PID 11785 的“颔语 · 设备控制台”。先确认设备在线且有新的“设备已响应”回执；再选“自选颜色”→“薄荷”、亮度约 30%，点“应用到灯板”。观察**手机回执和真实灯色**是否一致。接着点“试灯 5 秒”，记录红 → 绿 → 蓝 → 白 → 灭的顺序及结束后是否恢复薄荷；最后点“熄灯”，确认灯圈实际熄灭。

若手机写操作失败，请记录失败的是“应用”“试灯”还是“熄灯”、按钮/回执文字和设备是否掉线。此前手机只验证过面板加载及 `get` 查询；这一步才是云端写操作验收。下方串口脚本可作为**手机失败后的隔离复核**，会真的改变灯色并在结束时恢复原状态；运行前先断开 Chrome USB，并准备目视观察。此前串口和本地面板灯效已通过，正常情况下无需重复。

```sh
"$PY" tools/test_panel_device.py --port "$PORT" \
  --output .local/manual-tests-20261031/panel-serial-check.json
```

## 5. 两轴手动小幅试动（已完成；当前暂停复测）

当前集成固件的 P18 俯仰轴试动已获目视确认。P17 水平轴随后完成 `1500 → 1525 → 1500 → 1475 → 1500 µs → stop`，使用者亲眼看到底部舵机带动支架水平往返；最终回执为两轴 PWM 关闭。两轴画面反馈方向尚未标定；无需重复本项来证明电机可动。日志分别保存在 `.local/face-gimbal-tilt-trial.jsonl` 与 `.local/face-gimbal-session-20261031-154848.jsonl`。

以下命令仅保留作机械和供电问题解决后的复测记录，**现在不要运行 `arm`、`jog`、`dir` 或 `start`**。恢复试验时，先退出 Chrome 的 USB 连接，确认支架能安全承重、线材有余量，再启动保持同一串口连接的脚本：

```sh
"$PY" tools/face_gimbal_session.py --port "$PORT" \
  --output .local/manual-tests-20261031/p17-face-gimbal.jsonl
```

脚本会等待 USB 打开造成的启动，并要求连续两次 `status` 确认两轴 PWM 关闭；看到 `face-gimbal>` 提示后，依次输入下面几行，每输一行回车，并观察**底部水平轴**及画面左右变化。`arm` / `jog` 的空闲租期为 10 秒，超过后设备会自动关闭输出；这种情况下结束脚本并重新开始，不要连续追加移动命令。

```text
status
target
arm pan
jog pan +25
jog pan -25
stop
quit
```

`target`、`status` 只读；`arm` 和 `jog` 会让舵机实际输出 PWM。即使回执显示 `pan_us` 改变，也须以目视确认实际转动、异响和线材受力。`stop` 后核对 `pan_armed=false`、`tilt_armed=false`，但 PWM 关闭不等于支架实际处于安全角度。方向符号须由有效单脸画面的实际坐标变化确定，不凭接线或脉宽推测。

### 已定位：arm tilt 直接转到同一偏低位置

用户已完成手动定位：下移发生在 `arm tilt` 后，两次都到同一个偏低位置并稳定。断 USB 后未明显自行下垂，上电但未发命令时不动。无需重复 arm/stop 来定位时点。若串口会话尚未结束，先输入 `stop`，确认两轴 `armed=false` 后 `quit`；无法确认时托住支架并拔 USB。

当前 `arm tilt` 固定输出 1500 µs；这不是已标定的镜头朝前位置，也不是只移动 25 µs。下一步先在断电并托住支架后检查舵盘与摄像头固定片的相对安装角度，安排把 1500 µs 对应的位置校准为所需朝向；不要强拧舵机输出轴或带电拆装。具体重装点取决于实物支架，不凭软件轴名指定螺丝。当前固件没有设置 home 的命令，先不扩大脉宽范围，不启动自动居中。

证据：用户 2026-10-31 的两次目视反馈，以及 `.local/face-gimbal-session-20261031-160558.jsonl`、`.local/face-gimbal-session-20261031-160633.jsonl`。现有证据优先指向启动位置与镜头朝向不匹配；舵机电压未测，不认定供电已排除。
