## 已实现的操作

- 状态指示、自选颜色、熄灯三种模式；自选颜色支持 RGB 与亮度。
- “应用到灯板”发送设置，等待设备返回相同请求编号与实际设置。没有回执、超时或驱动报错时不会显示执行成功。
- “试灯 5 秒”由设备计时：红、绿、蓝、白、灭各 1 秒，随后恢复原模式；网页关闭不会让试灯永久持续。
- USB 串口与灵机官方 H5 SDK 两种传输。普通浏览器只能使用 USB；云端入口需要灵机 App / 小程序的设备上下文。
- 姿态诊断显示固件阶段、二维眼线倾角、检测目标数、推理耗时及设备报告帧龄。本地 USB 面板被动接收 `HV pose`，另外显示本页最近接收时间；云端使用属性快照。单帧帧龄不能代替 30 秒连续输入验收。
- 设备固件的 HP 快照曾遗漏 epoch 有效性：可能把核心拒绝的眼点显示为有效。修复通过回归与编译后已随[当前自检固件](../artifacts/headvoice-face-selftest-eligibility-20261031.json)上板，真实失效/恢复边界仍待验收；H5 v2 发布本身不会更新固件。当前手机灯控可独立验收，姿态有效性以 USB `HV pose` 与时序分析为准。
- 摄像头支持 USB 单帧获取和自动刷新，校验完整后显示实际画面；提供停止、接收进度、接收时间和耗时。此功能不会启动姿态模型，也不会上传图像。

默认状态模式、亮度 20%；重启恢复默认。面板 100% 对应 PWM 上限 48/255，避免联调时全亮。颜色图形只是预览；设备驱动返回成功仍需目视确认灯板。

状态模式在 HeadVoice stage 3 显示白色校准、黄色待确认、蓝色播放；baseline、stage 1/2 默认为灭。此前使用关闭姿态推理的 stage 1 对照验证 RGB 控制。当前 face stage 2 已显示真人姿态观测，但连续追踪与 400 ms 时序尚未通过，不作为灯控验证的前置条件。

面板没有重置配网、恢复出厂、动作播报、云台移动或 IMU 融合按钮。

## 摄像头画面

桌面 Chrome 打开本地面板，连接开发板 USB，待“设备已响应”后点击“获取画面”。“自动刷新”在一帧接收完毕后等待至少 3 秒再取下一帧；“停止刷新”停止后续请求，已经开始的传输会收完。切到其他页面也会停止自动刷新，重新进入时不会自行开启。断开连接或确认设备重启后清除画面。

stage 1 和目前的 face stage 2 应用都提供 `hv_camera snapshot`，无须为单帧预览重刷。原始图像为 120×160 RGB565LE，按当前装配旋转后显示 160×120；此前浏览器取帧约 7.4–7.5 秒，face stage 2 的一次取帧约 8.9 秒，不是实时视频。画面时间标注为接收时间，而非曝光时间。旧图保留时持续显示接收距今时间，损坏或未完整校验的帧不会覆盖旧图。

摄像头与灯光共用一个 Web Serial 连接。图像传输期间灯光保持原输出，并暂停设置、试灯及状态查询；结束后自动查询状态并恢复控制，避免额外串口回显干扰图像。解析检查 BEGIN、连续偏移、块长、帧长及 FNV-1a；超时 25 秒、丢块、校验失败、重启或断线会取消本帧。协议没有请求编号，失败后必须点击“断开”再重新连接，避免把迟到数据用于下一帧。

此版本仅支持桌面 USB 画面。本地灵机 H5 SDK 的设备快照接口返回属性数据，未发现可直接使用的摄像头视频请求接口；云端连接会禁用画面按钮并说明限制。图像只在当前页面内存中保留，不进入云端属性、打包文件或测试 JSON。验收截图含实际拍摄内容，仅保存在 Git 忽略的 `.local/`。

2026-10-31 实测单帧获取、连续自动刷新、停止后不再获取、断开清画面与灯控恢复均通过。39 项前端测试及生产构建通过；记录见 `artifacts/panel-camera-validation-20261031.json`。这是此前本地预览验收；后续功能随 H5 v2 发布，手机端仍没有 USB 图像传输能力。

## 平台与设备协议

`panel/protocol.json` 是 H5 与构建脚本共用的映射。平台产品页内部路径中的 `1531` 不是 PID。

| 服务 / 属性 | 标识 | 类型与权限 |
| --- | --- | --- |
| headvoicePanel | SIID 12 | 自定义服务 |
| Command / 面板指令 | PIID 1 | String，最长 96，只写，不支持语控 |
| Report / 设备回执 | PIID 2 | String，最长 640，只读，不支持语控 |

指令为 ASCII 字符串，请求编号范围 1–999999999：

```text
101 get
102 set 1 20 80 190 255
103 test
104 set 2 20 80 190 255
```

`set` 参数依次是模式（0 状态 / 1 自选 / 2 熄灯）、亮度 0–100、R/G/B 各 0–255。固件串口前缀为 `hv_panel`，例如 `hv_panel 101 get`；串口回执前缀为 `HP `，云端 Report 只含 JSON。

回执包含协议版本、设备启动编号、请求编号、驱动结果、设备运行时间、模式、颜色、输出、剩余试灯时间及姿态诊断。控制队列最多 4 条；非法指令或队列满不会执行。H5 同时只允许一个请求，10 秒超时，不自动重发设置/试灯；8 秒轮询，15 秒没有确认回执则禁用控制。未匹配的云端快照不能确认执行，也不能覆盖已显示的回执。

USB 检测到 ROM 启动标记时，立即撤销旧连接确认、取消旧请求并清除画面和姿态。随后最多 20 秒只重试 `get`；旧 boot 的缓冲回执和已取消请求都不能恢复“已同步”，必须收到新 boot 的匹配回执。重启前尚未确认的写入结果保持未知，不自动重发。

2026-10-31 此路径的主机回归覆盖旧 `get/set/test` 取消、旧 boot 与迟到编号拒绝、首个新查询丢失后恢复；47 项前端测试及生产构建通过。本地 H5 ZIP 已重新生成并确认包含新版被动诊断与重启保护，哈希见 `artifacts/panel-build-summary.json`；这些检查不代表新版包已完成手机或设备重启实测。

## 构建面板

使用兼容 Vite 8 的 Node.js（本机验证为 24.22.1）：

```sh
npm --prefix panel ci
npm --prefix panel test
npm --prefix panel run build
python3 tools/package_panel.py
npm --prefix panel run dev
```

上传包为 `artifacts/headvoice-panel.zip`，根目录含 `index.html`、`app.json`、`assets/`；不包含固件、产品密钥或源代码。哈希见 `artifacts/panel-build-summary.json`。官方 H5 SDK 来源见 `panel/vendor/README.md`。本机预览使用终端显示的 localhost 地址。

## macOS 固件构建

构建复用经过提交号及工作树校验的官方 SDK，不修改 SDK 本身：

```sh
export HEADVOICE_SDK="/Users/emt/Workspace/hackathon/ljyd_xjwb03_agent_public_developer"
export IDF_TOOLS_PATH="$PWD/.tools/espressif"
# 新机器首次安装官方工具；已有环境无需重复。
python3 "$HEADVOICE_SDK/esp-idf/tools/idf_tools.py" install xtensa-esp-elf esp-rom-elfs cmake ninja
python3 "$HEADVOICE_SDK/esp-idf/tools/idf_tools.py" install-python-env
# 仅在需要关闭推理做隔离对照时构建 stage 1；当前 face stage 2 的灯控和预览无需重刷。
python3 tools/build.py headvoice build --stage 1 --rotate-cw90
```

本机 Apple Python 3.9.6 的 `importlib.metadata` 无法识别新版 `ruamel.yaml` 的规范化包名，已在项目虚拟环境固定 `ruamel.yaml==0.18.6`、`ruamel.yaml.clib==0.2.8`。可在新机器使用 Python 3.12 创建 IDF 环境。本机产品身份在 Git 忽略的 `.local/cloud.json`，不要把密钥复制进面板或文档；缺少身份时构建会使用 SDK 示例 PID，烧录前必须核对。

## 接线后验证顺序

1. 断电接线：官方 8 灯 WS2812 的 DIN 接 GPIO1、5V 供电并共地；BF3901 使用 3.3V，接线沿用 README。MPU6050 默认 SDA8 与摄像头 D0 冲突，暂不按默认示例同时连接。
2. 枚举真实 USB 串口并关闭其他占用程序，保留当前已校验的 face stage 2 应用；灯控和预览无需切换固件。只有确需排查推理影响时才安排 stage 1 隔离对照。若需烧录，按对应镜像清单核对版本、分区与哈希；当前 face 模型内嵌应用 rodata，不要求为面板验证重写模型区或 NVS。
3. 用本地面板连接 USB，先读取回执，再测试自选颜色、亮度、熄灯、5 秒自动恢复、断开及重新连接。记录目视灯效与回执是否一致。
4. 手机进入奶龙设备页，继续测试设置、试灯、断网、超时和重连。手机加载与云端 `get` 已确认，但不能替代写操作和真实灯效验收。
5. 摄像头另行验证：stage 1 采集及当前 face stage 2 预览已有实测；下一步按[实机清单](next-device-tests-2026-10-31.md)改善取景或光照，采集持续正脸、左右侧倾、遮挡及多人日志。`HV pose` 的 `conversion_ms`、`model_ms`、`eye_span_px` 用于分辨转换耗时、模型耗时及小眼间距带来的角度量化。

```sh
python3 tools/pose_readiness.py artifacts/本次采集.jsonl
```

时序检查要求同一连续片段至少 30 个有效追踪观察、覆盖至少 30 秒；各帧帧龄不超过 400 ms，且相邻结果满足 `captured_ms[i] - captured_ms[i-1] + age_ms[i] <= 400`，保证下一结果到达前上一帧未被生产 core 判为过期。不能只分别检查帧龄和采集间隔，也不能跨重启、时间倒退或显式失效片段合并样本与时长；未换行的尾片段不计入资格。这个检查不证明中立稳定性或动作准确率。2026-10-26 的 27 个历史观察推理中位数 2676 ms、结果帧龄中位数 2721 ms、有效输入 0；它属于旧后端记录，不代表当前 face 性能。stage 3 真人组合、确认与播报仍待验收，400 ms 保护保持不变。

保持完成后经 9–14° 缓慢回正的状态丢失已修复；双方向、未完成保持、超时及失效帧有生产 C 回归覆盖，真人效果待复测。IMU 安装取舍见 [六轴用途](imu-options.md)。

## 10/31 实机状态补充

手机此前已确认 H5 v1 加载并显示设备响应，串口也记录云端 `get` 与匹配回执。早期 COCO stage 2 在联网运行期间反复 panic；当时的 80 MHz 内存配置、自检和堆检查未消除故障，不能认定是热点问题。该历史负结果不代表当前 face stage 2 的表现，见 `artifacts/panel-stability-20261031.json` 与 `docs/validation.md`。关闭姿态推理的 stage 1 首轮协议对照时灯圈未接；随后用户明确接好灯圈和 USB，完成下述实测。

桌面 Chrome USB 面板已验证连接、湖蓝 20%、薄荷 30%、试灯 5 秒后恢复、熄灯、断开时禁用按钮及重新连接读取设备状态。用户确认蓝色常亮、红绿蓝白灭顺序，以及恢复薄荷绿和熄灭均正常。两轮串口脚本也通过命令回执、交错查询去重和恢复检查。自动脚本中的初始蓝色仅持续约 62 ms，不能要求使用者据此判断蓝色是否正常；已用面板常亮另行确认。

实测发现预览区“待应用”为静态文本，已改为依据新鲜匹配回执显示“已同步”，发送设置期间显示“等待回执”；20 项现有前端测试和构建通过，重连后在真实设备上观察到“熄灯／已同步”。证据见 `artifacts/panel-wired-validation-20261031.json`。该次验收时修复仅用于本地，后续已随 H5 v2 发布；手机云端设置/试灯、长期稳定性和实时姿态仍未验收。本轮未烧录或发送云台运动指令，结束时设备保持熄灯。

当前生成配置采用 Flash/PSRAM 80 MHz，并保留启动内存自检和轻量堆检查；这是诊断配置，不代表已确认根因。设备保留最近 8 条写操作编号，交错的状态查询不会让重试的试灯重新计时。
