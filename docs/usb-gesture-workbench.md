## 喝水演示

1. 启动 `npm --prefix panel run dev`，在桌面 Chrome 打开终端给出的本机地址。
2. 接上开发板 USB，点击“连接 USB 设备”，选择 ESP32 串口。等待“设备已响应”和设备当前绑定。
3. 张开手掌填写“我想喝水”；V 字暂时留空。点击“保存到设备并核对”，等待写入及独立回读确认。
4. 如需检查取景，展开“摄像头与连接诊断”，获取一帧，等传输结束后再做手势。
5. 将单手掌心朝向摄像头，保持稳定。设备完成识别后，通过已有 Mac 中转将绑定原句送入 Agent；当前 prompt 要求向照护者以第三人称“用户”简短转述需求。
6. 确认一次张掌或 V 字后，板端暂停检测和分类，右侧保留本轮确认结果。在右侧核对真实回复文字，并听设备扬声器。目标示例为“用户想喝水了”，文字来自 Agent，网页没有预置成功回答。
7. 需要下一轮时，先移开手，等 Agent 事务结束，再点击“开始下一次”。网页重新连接、Agent 失败及手掌持续入镜都不会自动开始新一轮；设备重新启动会开启首轮。

USB 承担配置与诊断；设备仍需联网，Mac 中转仍需运行且持有有效的灵机凭据。单独连接 USB 不会替代云端语音链路。`/healthz` 返回 ready 只证明中转进程就绪。

## 设备词典协议

命令均经同一个串口写队列发送：

```text
hg_dict 101 get
hg_dict 102 set open_palm e68891e683b3e5969de6b0b4
hg_dict 103 set v_sign -
hg_dict 104 arm
```

`set` 的最后一项是 UTF-8 十六进制；`-` 表示空绑定。每项最长 180 字节，拒绝无效 UTF-8、控制字符和换行。隔离 SDK 的 CLI 输入缓冲为 512 字节，原始 SDK 不改。

`HGD` 回执包含 `v`、独立的 `boot`、请求 `id`、`ok`、`code`、`persisted`、`storage_error`、`bindings` 和实际 `max_age_ms`。设备在 NVS 的 `hv_gesture/dictionary` 中保存完整词典，提交成功后才替换内存值；保存与正在处理的手势互斥。提交失败保留旧内存值并撤销持久化确认。未保存时使用固件明确配置的默认绑定。

单次模式新增 `scan_supported`、`scan_armed`、`scan_generation`、`last_gesture`、`palm_count`、`v_count` 与 `agent_busy`。`arm` 仅显式开始下一轮，不修改词典或完成累计；Agent 忙碌或手势正交给工作线程时拒绝。网页每两秒只读查询暂停状态，不在重连时自动 `arm`。未报告此能力的旧固件显示不支持，网页不模拟板端暂停。

网页依次写入两个手势，再独立 `get` 核对完整结果。两次写入不是跨命令原子事务：第二条失败时第一条可能已保存，网页会撤销“已确认”并提示重新读取。超时不自动重发写入。重启或断开会清除页面确认，旧回执不能恢复连接。

## 观测与回复的边界

- `HG observation` 是原始分类诊断；累计完成次数来自设备，不由页面逐帧累加。帧龄上限采用匹配的 `HGD.max_age_ms`，当前固件为 1000 ms。
- `HG_AGENT` 带独立 boot 和手势事务 ID，报告 connecting、sending、accepted、speaking、失败及完成状态。网页只接受已确认设备启动后的同一事务。
- 新诊断源码会为 `unavailable` 附上失败当时捕获的 `detail`：云端未连接、已有语音会话、本地音频占用、手势会话未释放、生命周期锁忙或 SDK 启动失败等。保留原错误码；多个条件同时阻塞时报告按原顺序遇到的首项。页面首次收到 `unavailable` 也保留并显示原因。此诊断固件于 2026-11-01 编译通过，尚未烧录。
- 新增 `hg_agent status` 只读诊断，输出 `HG_AGENT_STATUS`。其中 `ready` 只表示本地启动门槛通过，不表示远端已加入；旧板上固件尚不支持此命令。
- `failed` 可带 `phase: connecting/sending/reply`；`code:-2` 表示超时。连接阶段还带无凭据的 `detail`，用于区分等待远端、等待运行状态或音频流仍活动等条件。
- `reply` 仅转发该自动事务拥有的 TTS 文本，保留截断标志。文字回调捕获所属 ID，不能将旧回复归入下一事务。
- accepted 表示请求被接受；speaking 表示 SDK 开始播放。VB701N 缺少硬件播放完成确认，`playback_completion_unsupported` 不显示为已确认播完。实际声音仍需听测。
- 长时间取图可能使状态回执过期，期间的 Agent 状态可能被忽略。演示先取景、后做手势。
- 诊断区展示原始类别、分数、分差、候选连续帧数及采集间隔；设备门槛与页面参考解释分开。最近 200 条手部观测可导出到本机，采用字段白名单，不包含云凭据、绑定或 Agent 文本。图片仅在同一连接与启动、`captured_ms` 和尺寸精确匹配时附检测框。

## 语音启动 -7 排查（2026-11-01）

页面第 5 次请求显示 `unavailable / -7`。源码确认它发生在 `begin()` 返回失败后、提交 prompt 之前；`-7` 是本地 `-QM_EBUSY`，不能解释成云端 Agent 拒绝了需求。旧实现把云端未连接、会话占用、锁忙等条件合并，没有保存本次具体分支。

两次串口打开后均观察到设备启动标记，因此后续采样不是原第 5 次失败的内存现场。两轮启动分别先出现两次 `reason=2`（Wi-Fi authentication expired），之后获取 IP、自动连上 MQTT 云端；应用日志约 25 秒报告 `cloud connected`。用户也说明没有操作、设备自行恢复。该证据支持网络就绪延迟是候选原因，但不能反向证明原第 5 次必然因云端未连接失败。

云端连接后，用现有板上固件连续做两次独占诊断会话：均 `connecting → ready → aborting → ended(code=0)`；主动 abort 中的 `failed(code=-9)` 是预期中断。没有提交文字需求、没有开启 probe 麦克风上传，也未验证实际出声。两段短日志未见 panic，不据此认定稳定性通过。网页 USB 已恢复连接并回读两项持久化绑定。

本轮补充失败原因与只读状态接口，29 项针对性 Python 测试、11 项页面 Agent 测试、面板生产构建及 ESP32-S3 固件编译通过。诊断应用 SHA256 为 `d40395ed65b5463e415400ef553220a7c6eaf7883b8a64fcb6bd91a9abfca493`；未烧录、未上传 H5、未推送。详见[排查证据](../artifacts/voice-minus7-diagnosis-20261101.json)。
