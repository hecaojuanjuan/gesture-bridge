# 六轴传感器在颔语中的用途（2026-10-31）

当前视觉目标是张掌与 V 字，对应原生分类器的 `five` / `two`；头部姿态和自动居中暂缓。本地外设资料对应 MPU6050，SDK 已有加速度（g）与角速度（°/s）读取接口，但尚未连接和实测模块，当前固件没有启用六轴采样、运动门控或相应面板功能。资料型号不等于已经确认手上芯片的版本和兼容性。

最有价值的用途取决于安装位置：

| 安装位置 | 能提供的信息 | 适合的用途 | 边界 |
| --- | --- | --- | --- |
| 摄像头支架 | 摄像头自身的转动与振动 | 支架被碰动时暂停手势确认；稳定后用新鲜帧重新积累保持时间 | 测的是相机运动，不能推断用户手指形状 |
| 用户头带 / 眼镜等固定佩戴位置 | 头部相对重力的倾斜、短时转动 | 历史候选：独立的头部动作输入，目前暂缓 | 增加佩戴负担，需要重新定义和验收输入规则 |
| 手持控制器 | 控制器自身的转动与晃动 | 可另行研究手动输入或测试辅助 | 无法直接区分张掌、V 字；“摇一摇取消”尚未实现，不放进当前面板 |
| 桌面主板 | 设备被拿起、倾倒或移动 | 装配与设备移动提示 | 底座静止时不一定反映支架运动，更不能测量用户手型 |

当前优先建议验证“支架运动门控”，作为视觉确认的附加失效条件。运动期间清除尚未完成的候选保持，稳定后只用新鲜帧重新积累；已经触发的手势去重锁存应保留，不能把设备晃动当作用户松手，避免恢复后重复触发。允许再次触发仍需满足真实的释放条件。这是待实现方案，不需要头部“中立校准”，也不重启自动居中开发。

RGB 可以在未来提示“设备移动，暂缓确认”，但当前没有该灯效或状态字段，不添加可操作的面板入口。六轴不能直接识别五根手指或张掌 / V 字，也不能修复过曝、遮挡、截手或模型误分类。不要把一次摇动直接连到播报、重置 Wi-Fi 或恢复出厂设置。

六轴只有加速度计与陀螺仪。静止或缓慢运动时可从重力方向估计倾角；线性加速会干扰这个估计，陀螺仪积分也会累积漂移。没有磁力计时不能把长期绝对航向当作已知量。它不提供头部在空间中的绝对位置，也不能证明情绪、专注度或健康状态。

## 接线冲突与实施前提

SDK `apps/main/peripheral/bsp_mpu6050.c` 默认 I2C0、SDA=GPIO8、SCL=GPIO9、地址 0x68；BF3901 摄像头 D0 同样使用 GPIO8，控制 I2C0 则使用 GPIO21/47。直接启用默认示例既会占用摄像头数据线，也会尝试把同一 I2C 控制器配置到另一组针脚。

共享摄像头的 GPIO21/47 是一个可行性候选，尚未接线和验证。当前摄像头驱动地址为 0x6E，MPU6050 地址为 0x68 或 0x69，没有已知地址重叠；本地 `i2cdev_get_shared_handle()` 可提供受管总线句柄，`esp_video_init_sccb_config_t` 也支持 `init_sccb=false` 并接收现有句柄。但当前两个驱动分别调用 `i2c_new_master_bus()`，不能只改 MPU 引脚或重复初始化就视为完成共享。必须统一总线所有权、初始化顺序、并发访问锁和失败清理，验证一方重连或退出不会删除另一方仍在使用的总线，并核对电平和上拉。本文不指定另一组替代针脚。

其他占用包括摄像头 GPIO4/13/8/41、RGB GPIO1、音频 UART/流控 GPIO40/39/38、日志 GPIO43/44、复位按键 GPIO14；舵机实体接线保留 GPIO17/18，当前 hand 固件报告 `servo_control=false`。还需核对 Flash/PSRAM、启动引脚和实物引出脚，不能把库中其他开发板的音频引脚表当作本板接线。

资料中的模块原理图画有 5V 输入到 3.3V 的 LDO，SDA/SCL 各经 4.7 kΩ 上拉至 3.3V，AD0 下拉。MPU6050 芯片自身的 VDD 规格是 2.375–3.46V，不能将模块输入端与芯片供电端混为一谈；实际模块供电仍须核对实物版本。随附“新版兼容”说明建议跳过不同芯片 ID，但当前 SDK 的 `mpu6050_init()` 本来就没有该 ID 拒绝分支，不能据此盲目改驱动或宣布兼容。

实施时先确定安装位置、总线与供电，再实现明确可关闭的采样任务。现有 SDK 每秒打印一次读数只适合连通检查，不是已经实现的运动门控；可先用较高频率同步记录静止噪声、偏置、轻碰和手动小幅移动，再选滤波、角速度门限和稳定时间。需保存覆盖图像采集至确认时刻的 IMU 历史，不能只用“现在静止”证明此前拍摄的帧也稳定。

当前张掌原生分类首测中，19 次有效分类帧的整帧推理中位数为 473 ms，其中分类阶段中位数 210 ms；最大结果年龄 583 ms。这是一个短窗试验，不是准确率或长期稳定性验收，见 [张掌首测记录](../artifacts/hand-native-palm-pilot-20261031.json)。现有手势门限为至少 3 个样本、保持 600 ms、最大帧龄 600 ms、释放 500 ms；增加 IMU 不会降低模型耗时，也不能成为放宽这些门限的依据。COCO / face 的旧性能和俯仰实验仅作历史，见 [旧设备测试记录](next-device-tests-2026-10-31.md)及 [2026-10-26 姿态统计](../artifacts/pose-accuracy-summary.json)，不代替当前 hand 后端数据。

## 历史俯仰异常的诊断候选（当前暂缓）

2026-10-31 的集成试验出现过俯仰支架突然大幅下移，串口只记录了 `arm tilt 1500 µs` 和 `stop`，没有实际角度反馈。若将 MPU6050 固定在随俯仰轴转动的摄像头支架上，可以在后续实验中同步记录角速度、静止时相对重力的倾角，以及 arm/stop 的时间点，帮助区分“命令已发出”和“支架何时实际转动”。这仍是待实现的诊断方案，当前控制面板不显示未测得的机械角度。

它不能单独判断电源压降、舵盘打滑或舵机内部故障，也不能阻止断电时的机械位移。两只舵机目前共用开发板 5V/VBUS；若整个主板掉电，板上 IMU 同样可能中断记录。电压和机械原因仍需分别核对，不能把 IMU 日志或 PWM 回执当成供电合格证明。

后续若恢复该诊断，再以静止和手动小幅移动确定安装轴、偏置与噪声；已确认方向的单轴动作也需单独安排。当前不把 IMU 接入舵机补偿回路，不扩展云台算法；未完成实测前不开放产品按钮。
