# 六轴传感器在颔语中的用途（2026-10-31）

本地外设资料对应 MPU6050，SDK 已有加速度（g）与角速度（°/s）读取接口。本轮没有连接模块，没有启用六轴采样或把下面的建议写成可操作的产品功能。

最有价值的用途取决于安装位置：

| 安装位置 | 能提供的信息 | 适合的用途 | 边界 |
| --- | --- | --- | --- |
| 摄像头支架 | 摄像头自身的转动与振动 | 当支架被碰动或云台移动时，暂停接受视觉动作；稳定后重新中立校准 | 测的是相机运动，不能据此说用户转头 |
| 用户头带 / 眼镜等固定佩戴位置 | 头部相对重力的倾斜、短时转动 | 可研究替代摄像头的 A/B 侧倾输入，改善遮挡和低光下的可用性 | 增加佩戴负担；必须固定朝向、校准零点，并重新验收确认规则 |
| 手持控制器 | 手部转动与晃动 | 提供独立的手动输入或测试辅助 | “摇一摇取消”容易误触，尚未实现，不放进当前面板 |
| 桌面主板 | 设备被拿起、倾倒或移动 | 装配与设备移动提示 | 桌面静止时不能测量用户头部姿态 |

当前优先建议先验证“支架运动门控”：它补充视觉失效条件，不改变两动作编码与新动作确认。若目标用户愿意佩戴，再单独评估 IMU 作为动作输入的方案。不要把一次摇动直接连到播报、重置 Wi-Fi 或恢复出厂设置。

六轴只有加速度计与陀螺仪。静止或缓慢运动时可从重力方向估计倾角；线性加速会干扰这个估计，陀螺仪积分也会累积漂移。没有磁力计时不能把长期绝对航向当作已知量。它不提供头部在空间中的绝对位置，也不能证明情绪、专注度或健康状态。

## 接线冲突与实施前提

SDK `apps/main/peripheral/bsp_mpu6050.c` 默认 I2C0、SDA=GPIO8、SCL=GPIO9、地址 0x68；BF3901 摄像头 D0 同样使用 GPIO8，二者不能照默认示例同时接线。摄像头还占用 GPIO21/47（控制 I2C）、4/13/8/41；当前云台用 GPIO17/18，RGB 数据线为 GPIO1。还需核对主板的音频、Flash/PSRAM、启动引脚和实际引出脚，不在没有完整引脚表与实物核对时指定替代针脚。

实施时需要先确定模块安装位置、空闲引脚与供电，再实现明确可关闭的采样任务。建议先记录静止噪声、偏置、轻碰、云台移动与真人动作样本；滤波、角速度门限和稳定时间应从这些记录选取。融合方案必须用同步时间戳，不能拿当前 IMU 值直接校正几秒以前的摄像头结果。早期 COCO 路径约 2.68 秒的推理瓶颈不能靠增加 IMU 消除；后续 face 后端两轮采样的推理中位数约 134–140 ms，当前主要缺口是连续检测与真人动作验收，不能继续把旧模型耗时当成新后端性能。

## 当前俯仰异常中的用途

2026-10-31 的集成试验出现过俯仰支架突然大幅下移，串口只记录了 `arm tilt 1500 µs` 和 `stop`，没有实际角度反馈。若将 MPU6050 固定在随俯仰轴转动的摄像头支架上，可以在后续实验中同步记录角速度、静止时相对重力的倾角，以及 arm/stop 的时间点，帮助区分“命令已发出”和“支架何时实际转动”。这仍是待实现的诊断方案，当前控制面板不显示未测得的机械角度。

它不能单独判断电源压降、舵盘打滑或舵机内部故障，也不能阻止断电时的机械位移。两只舵机目前共用开发板 5V/VBUS；若整个主板掉电，板上 IMU 同样可能中断记录。电压和机械原因仍需分别核对，不能把 IMU 日志或 PWM 回执当成供电合格证明。

建议第一阶段只做同步记录和支架运动期间的视觉输入门控，不把 IMU 直接接入舵机补偿回路。先以静止、手动小幅移动和已确认方向的单轴动作确定安装轴、偏置与噪声，再设计阈值；未完成这些实测前不开放产品按钮。
