# Gesture Bridge 维护说明：配网复位、调试与版本核对

本文供维护人员使用。日常操作只需查看[用户使用说明](device-user-guide.md)，无需启动本地网页或串口终端。以下保留诊断、历史版本及换网操作，不能将这些步骤当作每次开机的前置要求。

## 2026-11-01 灯板逻辑核对

- 上电 `hv_light_init()` 清零模式，对应 `HV_LIGHT_STATUS`。灯光模式只保存在运行内存中，重启恢复状态指示；面板初始自选颜色仅是草稿，连接时只发 `get`，不会自动覆盖设备灯光。
- native 手势版的第二目标为 V 字。`feedback_publish()` 只接受分类器就绪、当前 epoch、已确认且仍有效的目标；`feedback_light_locked()` 对张掌输出 RGB `(0,32,0)`，对 V 字输出 `(0,0,32)`，其余输出全零。`bsp_ws2812_fill()` 将同一颜色写到所有灯珠，不是绿蓝两颗分别同时亮。
- 确认需要至少 3 个不同采集帧、持续至少 600 ms，分类分数至少 0.80，领先次高至少 0.20。图中的“保持约 3 秒”是操作建议，不是固件固定计时器或成功保证。
- 灯色跟随当前仍有效的确认状态，不是永久保存的成功记录；采集帧龄超过 600 ms 后由反馈任务清零，反馈和面板任务各约 50 ms 调度一次。灯可能短亮后熄灭，也可能恢复同一已确认手势的灯色而不增加完成次数。未亮灯不能区分等待、失效、无手、缺模型或硬件问题，不能标成独立的“失败灯”。
- 自选颜色、熄灯会覆盖状态输出；试灯优先级最高，5 秒后回到原模式。试灯期间红、绿、蓝、白、灭属于测试序列，不是手势或配网结果。状态模式直接输出状态 RGB，不受自选颜色亮度滑杆控制。
- 静态核对覆盖 `headvoice/core/hv_light.c`、`headvoice/core/hv_hand_gate.c`、`headvoice/firmware/hv_hand_app.c`、`headvoice/firmware/hv_panel.c`、官方 `bsp_ws2812.c` 和 `panel/src/main.js` / `cloud.js`。
- 主机验证：生产灯控 C 测试通过；手势 gate / app 的 6 项测试通过（含 gate 的 14 个场景和 native 张掌／V 字灯色、过期清灯、缺模型）；面板生命周期及协议 40 项通过。Windows 首次运行受沙箱临时目录及测试读取 CRLF 影响，改用工作区临时目录、GCC 和只归一化换行的面板临时副本后通过；未修改生产代码或原测试文件。本次没有连接实机，不能代替当前灯板亮灯、线序及识别准确率验收。

版本：2026-11-01。适用于 XJWB03 开发板、PID 11785，以及最近一次已确认部署的张掌／V 字 native 手势固件。

## 先记住这一句话

**是的，上电后就会自动启动手势识别；摄像头和模型正常初始化后即可尝试手势。不需要输入“开机”或 `start`，不需要按 BOOT，也不需要先连接热点或说唤醒词。**

这句话针对当前已部署的手势识别功能。**自动居中目前未启用，摄像头不会自动转动。** 语音对话和手机云端控制需要联网；开机音不能证明所有功能已就绪。

## 1. 开机：接上 USB 供电

1. 将 USB Type-C 线插到底板 USB 口，另一端接电脑供电。
2. 设备上电后启动，摄像头与手势模型会自动初始化；初始化成功后持续在板端识别。
3. 第一次使用时，按第 2 节在 USB 面板确认分类器已加载、观测持续更新。不要只凭开机音判断识别已经就绪。

日常开机不需要烧录固件、不需要重复配网。识别程序运行在开发板上，电脑只用于供电、查看诊断或设置；关闭网页不会停止识别。若 USB 是唯一电源，拔线会让整机关闭。

## 2. 手势识别：上电自动运行，完整手掌入镜

### 第一次先确认识别已经启动

按第 5 节打开电脑本地面板，再依次操作：

1. 点击“连接 USB 设备”，选择开发板的实际串口，等待“设备已响应”。
2. 看“手部诊断”：应显示 **“11 类分类器已加载”**，且“本页最近接收”持续更新。若显示“分类器未加载”，先处理模型或固件问题，不靠反复摆手启动。
3. 点击“获取画面”，确认掌根、掌心、指尖完整入镜。确认后停止自动刷新，让诊断数据恢复更新；取图期间本页会暂停诊断显示。
4. 若要看识别灯效，选择 **“状态指示”→“应用到灯板”**，等待设备回执。这个设置只控制灯光显示，不负责启动识别。

### 实际做手势

1. 一次伸出一只手，掌心朝向摄像头，保持完整入镜。
2. **张开手掌约 3 秒 → 完全移出画面约 2 秒 → 再做下一次。** 一直保持同一手势不会反复累计。
3. 查看“设备本次启动累计”中的张掌次数是否增加。状态指示模式下，固件规定稳定确认张掌后显示绿色。
4. V 字可以用相同节奏尝试；规则为稳定确认后 V 字次数增加、显示蓝色。**张掌已有成功记录，但此前两轮 V 字测试均没有完成事件，V 字尚未通过实测。** 没反应不一定是没有开机或没有联网。

“分类原始候选”只是单帧结果，累计次数增加才表示完成一次稳定保持。自选的绿色或蓝色灯光不代表识别成功。当前手势结果为计数和状态灯，**尚未接通手势对应的短句播报**。

只做手势识别可以不联网。需要语音对话或手机控制时，再执行下一节。

## 3. 配网：按是否保存过 Wi-Fi 选择一种情况

### 情况 A：已经配过网，网络名称和密码没变

1. 开启原来的路由器或手机热点，保持网络可用。
2. 给设备上电，它会尝试连接已保存的 Wi-Fi。
3. 打开配套微信小程序，确认账号下的设备显示“在线”。

不需要重新添加设备或再次输入密码。原热点只是临时关闭时，先打开原热点，不必清除配网。

### 情况 B：第一次配网，设备没有保存 Wi-Fi

1. 给设备上电，手机靠近开发板。没有保存 Wi-Fi 时，当前固件会自动进入蓝牙配网。
2. 打开手机蓝牙，登录配套微信小程序，按提示允许蓝牙、附近设备或定位权限。
3. 进入小程序“添加设备 / 配网”，选择对应产品或发现的设备。当前项目 PID 为 **11785**，已有平台发布记录中的产品名为“奶龙”。
4. 选择可以上网的 **2.4 GHz Wi-Fi**，输入正确密码。手机热点也要提供 2.4 GHz 网络；只有 5 GHz 的网络不可用。
5. 按小程序提示完成配网和账号绑定，保持设备供电、网络开启。
6. 等待设备出现在当前账号下，并显示 **“在线”**。

蓝牙负责把 Wi-Fi 信息传给设备，通常不需要先到系统蓝牙设置中手动配对。配网成功后再次上电会尝试连接保存的网络。

### 情况 C：换了 Wi-Fi 名称或密码，需要重新配网

已保存 Wi-Fi 的设备不会因为旧热点不可用就自动进入蓝牙配网。需要先清除旧配置，再按情况 B 操作。

1. 用 USB 数据线连接底板和电脑。
2. 若网页已连接设备，先点“断开”，并关闭其他占用同一串口的程序。
3. 打开串口终端，选择开发板实际 COM 口；参数为 **115200、8N1、无流控**。此前端口为 COM3，以本次设备管理器显示为准。
4. 可先输入以下只读命令并回车，核对 PID：

   ```text
   hv_provision status
   ```

5. **确定要清除旧网络后**，在串口终端输入以下命令并回车：

   ```text
   hv_provision restart
   ```

6. 设备清除保存的 Wi-Fi、配网环境和本地绑定标记后重启。看到 `ble provision start ret=0` 表示蓝牙配网已启动，然后按情况 B 完成手机配网。

**`hv_provision restart` 是重配网命令，不是普通开机或识别启动命令。** 它不会整片擦除固件或模型，也不会向云端请求删除旧账号中的设备。若提示已被其他账号绑定，需要由原账号处理解绑。

## 4. 语音对话：联网后唤醒

1. 确认热点或路由器开启，小程序显示设备“在线”。
2. 对着麦克风说 **“你好，小鹰”**。
3. 听到唤醒提示后，再提问，例如“现在几点了？”
4. 听到实际语音回答，才能确认这次对话成功。

唤醒词用于语音，不负责启动摄像头或手势识别。只响提示音、没有回答时，需要检查云端及语音链路；不能以开机音替代语音对话验证。

## 5. 控制面板：怎样打开、有什么用

### 电脑 USB 面板

在本项目电脑的 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'C:\Users\jiawa\Desktop\gesture-bridge'
npm --prefix panel run dev
```

保持终端窗口开启，用桌面 Chrome 或 Edge 打开终端显示的本地地址，通常是 `http://127.0.0.1:5173/`，端口以实际输出为准。首次运行若提示找不到 `vite`，先执行 `npm --prefix panel ci` 安装项目锁定依赖，再启动。

连接开发板 USB，关闭其他占用串口的程序，点击“连接 USB 设备”，选择实际开发板端口，等待“设备已响应”。

| 要做什么 | 面板操作 |
| --- | --- |
| 看识别是否运行 | 查看手部诊断中的分类器状态、新观测及累计次数 |
| 看一次摄像头画面 | 点击“获取画面” |
| 连续查看画面 | 点击“自动刷新”；结束时点击“停止刷新” |
| 显示手势状态灯 | 选择“状态指示”，再点“应用到灯板” |
| 自选灯色 | 选择“自选颜色”，设置颜色和亮度，再应用 |
| 关灯 | 选择“熄灯”，再应用；设备识别仍继续运行 |
| 结束网页连接 | 点击“断开”；不会关闭整机或停止板端识别 |

USB 回执只证明本地通信，不证明设备已经连云。网页“获取画面 / 自动刷新”只控制预览，不是识别开关。当前面板没有重配网或开启自动居中的按钮。

### 手机小程序面板

打开配套微信小程序 → 找到已绑定且在线的设备 → 进入设备控制页。手机云端面板依赖小程序的设备上下文；复制电脑的本地地址到手机不会自动连接开发板。

手机已发布的 H5 v2 与本地开发版功能可能不同；摄像头画面和新增手部诊断以电脑 USB 面板为准。

## 6. 自动居中：当前版本没有启用

**当前已部署的张掌／V 字手势固件不包含舵机控制，摄像头不会自动转动。上电、联网、说唤醒词或打开预览都不会启动自动居中。**

最近一次部署与实机启动记录均为 `servo_control:false`。仓库虽然另有带云台的 face / face-hand 代码，但需要另行集成、部署，并核对机械中位、两轴方向与可用目标后才能开启。

此前俯仰轴在 `arm tilt` 后曾明显向下转，方向标定和闭环居中尚未验收。因此 `hv_gimbal start`、`hv_gimbal auto on` 不是当前手势固件可以直接使用的日常开关；不要照旧文档尝试一组运动命令。当前先通过调整整套装置摆放和手的位置，让完整手掌入镜。

## 7. 关机与实体按键

**关闭整机需要断开供电。** 仅由 USB 供电时，拔掉 USB；如另有电池或外接电源，也需要关闭相应电源。网页“断开”和“熄灯”都不等于关机。

| 按键 / 开关 | 作用及当前确认范围 |
| --- | --- |
| `EN` | 主控复位重启，不是关机；普通复位不主动清除 Wi-Fi |
| `BOOT` | 用于进入烧录模式；正常使用不用按，不要按住它再开机 |
| GPIO14 配网按键 | 固件支持低电平长按约 3 秒触发重配网；实体对应哪颗按钮尚未确认 |
| `SW1` 拨动开关 | 资料不足，尚未确认用途或开关方向，不把它当作已确认的电源开关 |

GPIO14 长按会先请求云端复位 / 解绑；请求失败时清除本地配网并重启，请求被接受则等待云端复位事件。它与第 3 节的串口命令清除范围不同。未确认实体接线前，不把 BOOT、EN 或 SW1 当成配网键。

## 8. 遇到问题先看这里

| 现象 | 判断与处理 |
| --- | --- |
| 不知道在哪里输入“开机” | 不需要输入；当前识别上电初始化后自动运行 |
| 有开机音但不识别 | 查看分类器是否已加载、观测是否更新、整只手是否入镜；开机音不证明模型就绪 |
| 手势计数增加但灯色不变 | 切回“状态指示”并应用，排除自选颜色或熄灯模式 |
| V 字一直没反应 | 当前 V 字尚未通过实测，不要据此判断未开机或未联网 |
| 有开机音、已联网，但摄像头不转 | 当前手势固件没有自动居中功能，不是少了一条启动命令 |
| 小程序找不到设备 | 检查蓝牙权限；已经保存 Wi-Fi 时，要换网请先按第 3 节清除旧配置 |
| 换热点后一直离线 | 恢复旧热点名称和密码，或重新配网；确认提供 2.4 GHz 网络 |
| 有唤醒提示但没有语音回答 | 检查设备在线状态和语音链路，提示音本身不算对话成功 |
| 电脑找不到串口 | 检查 USB 数据线、开发板端口及驱动；只供电的线不能传串口数据 |
| 关了网页设备还在运行 | 正常；板端识别独立运行，关机需要断开供电 |

## 9. 版本与核对依据

本说明依据最近一次已确认烧录的手势版，并非本次重新连接设备后的实时状态。若后来从其他窗口刷过固件，应先核对实际运行版本。

串口 115200 8N1 下，手势版启动时会自动输出 `HG` 的 `event:"ready"`，包含 `backend:"hand"`、`classifier:"espdl_gesture11"`、`classifier_ready:true` 和 `servo_control:false`；之后应持续有 `event:"observation"`。ready 只在启动时输出一次，没录到时可结合持续观测中的分类器状态核对。无需发送启动命令，网页与终端不能同时占用串口。

功能依据：[部署清单](../artifacts/headvoice-hand-palm-v-native-20261031.json)、[启动记录](../artifacts/hand-native-startup-20261031.json)、[手势实测](hand-gesture-tests-2026-10-31.md)、[配网验证](validation.md#新设备重新配网与账号绑定)、[面板说明](control-panel.md)、[历史自动居中记录](camera-auto-center.md)。供电与实体按键说明另核对了本地官方板卡手册；SW1 和 GPIO14 的实物对应关系仍待确认。

固件中 `tools/prepare_sdk.py` 接入上电启动，`headvoice/firmware/hv_hand_app.c` 初始化摄像头与推理，`headvoice/firmware/integration.cmake` 决定是否包含云台。当前识别不以 Wi-Fi 连接作为启动条件，但仍需摄像头、内存与模型等正常初始化。

本次只整理说明和操作图，没有修改、烧录固件，没有清除网络，也没有执行舵机运动。
